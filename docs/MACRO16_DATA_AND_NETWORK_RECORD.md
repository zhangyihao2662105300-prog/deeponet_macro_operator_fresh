# Macro16 Data Generation And Network Record

Date: 2026-06-27

This note records the current Macro16 data-generation contract and neural
network contract after the wind-shell generation correction. It is a record
only. It does not change model code, training code, or the 128-point integration
rule.

## 1. Current Route

The active route is Macro16 v4:

- 16 boundary control nodes.
- 48 boundary displacement DOFs.
- Standard fixed source128 integration rule.
- Real geometry comes from `X16_raw`.
- Model-visible geometry is `X16_hat`.
- Model-visible displacement is `q48_def_hat`.
- Output label is `LE_macro`.
- B supervision is `B_macro_qdef`.

Do not use:

- active42 as the main route;
- CSS8 internal nodes as model inputs;
- `X_macro` as model input;
- old TRUE176 `LE/B` labels as new wind-shell labels;
- synthetic mixed `q48` as formal wind-shell training data.

## 2. Abaqus Data Generation Method

The formal wind-shell Abaqus data-generation method follows the original
2000-epoch TRUE176 shape4 training-data route.

The displacement source is:

```text
TRUE176 full48_vector.npy
```

The data generation pipeline is:

```text
TRUE176 full48_vector.npy
-> reorder legacy TRUE176 full48 order to shape4/Macro16 keep-node order
-> decompose q48 into legacy local axes
-> divide by legacy H2 to get a dimensionless local displacement template
-> rebuild the template in the target wind-shell keep-node local frames
-> scale by target L_ref
-> write 100-frame Abaqus displacement history
-> run one base Abaqus job
-> run 48 forward perturbation Abaqus jobs
-> export fresh target LE and B labels from Abaqus
-> build complete compact
-> rebuild Macro16 source128 compact
-> run data-contract and selected-frame force audits
```

Important:

- TRUE176 is used only as the source of complete `q48` displacement templates.
- TRUE176 old `LE128_base` and `B_LE128_forward` are not reused as labels for
  the new wind-shell target geometry.
- The new target geometry must always get fresh Abaqus `LE` and forward
  perturbation `B`.
- The formal default is 100 increments, not 10.

The current script is:

```text
scripts/run_gate04_wind_shell_generality_audit.py
```

Formal defaults:

```text
--q-source-mode true176-template
--increments 100
--true176-vector-kind full48
```

The old synthetic path remains only for compatibility smoke tests:

```text
--q-source-mode synthetic-mixed
```

## 4. Rigid Motion Preprocessing

The data loader prefers rigid-removed displacement:

```text
q48_def_hat
```

The raw Abaqus displacement remains stored:

```text
q48_raw
```

The input is still 48-dimensional. Rigid motion is removed by preprocessing;
the route does not delete six DOFs and does not create a 42-dimensional input.

Current B chain:

```text
B_macro_qraw  -> physical assembly/audit
B_macro_qdef  -> network Sobolev supervision
```

The rigid projection currently uses a small-rotation linearized chain
approximation. It is not a strict nonlinear Kabsch Jacobian.

## 5. Network Input And Output

Training entry:

```text
src/macro_deeponet/train_macro16_boundary_sobolev.py
```

Current default model style:

```text
--model-style le0
Macro16BoundaryDeepONetWithLE0
```

Model-visible inputs:

```text
q48_def_hat                  [48]
X16_hat.flatten()            [48]
L_ref or length-scale scalar [1]
macro16 point features       [128,F]
```

The branch vector is:

```text
[q48_def_hat, X16_hat.flatten(), L_ref]
```

So the default branch dimension is:

```text
48 + 48 + 1 = 97
```

The point/trunk feature dimension is inferred from compact point features
generated by the Macro16 source128 builder. The point count remains:

```text
128
```

Network output:

```text
LE prediction [batch,128,6]
```

B prediction:

```text
d(LE prediction) / d(q48_def_hat)
```

B is not a separate output head in the default route. It is obtained by
automatic differentiation of the LE output with respect to the 48-dimensional
model-visible q input.

## 6. Default Network Structure

Current default model:

```text
Macro16BoundaryDeepONetWithLE0
```

Default hyperparameters in the training entry:

```text
basis_dim    = 96
hidden_dim   = 384
branch_depth = 5
trunk_depth  = 5
activation   = tanh
```

Main parts:

```text
point LE0 head:
  LE0(point)

point B baseline:
  B_base(point) @ (q - q0)

DeepONet residual:
  branch([q48_def_hat, X16_hat, L_ref]) dot trunk(point_features)

output:
  LE = LE0(point) + B_base(point) @ (q - q0) + residual(q, geometry, point)
```

The residual is zero-initialized by default through the model construction.

## 7. Training Loss Contract

Main loss terms:

```text
LE loss
AD B loss
rigid loss
```

Default training parameters in the current entry:

```text
epochs                     = 120
batch_size                 = 4
eval_batch_size            = 2
lr                         = 8e-5
lr_decay                   = 0.9995
weight_decay               = 1e-5
jacobian_loss_scale        = physical-balanced
jacobian_columns_per_batch = 8
rigid_loss_weight          = 0.1
optimizer                  = AdamW
```

The Jacobian target relation is:

```text
J_norm = B_macro_qdef * q_std / LE_std
B_macro_qdef = J_norm * LE_std / q_std
```

Physical force/stiffness audits do not use `B_macro_qdef`; they use:

```text
B_macro_qraw
integration_weight_phys
```
